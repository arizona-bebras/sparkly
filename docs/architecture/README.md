# Архитектура

> Текущий каркас репозитория упрощён до `backend/`, `frontend/`, `agent/`, `ml/` и `analytics/`. Ниже описана целевая схема системы; остальные компоненты пока не имеют отдельных проектов.

## Потоки данных

1. Агент отправляет Protobuf-телеметрию через mTLS/HTTP2 в Caddy; Caddy направляет её в ingest. Adopt-запросы идут через Caddy в Control Plane.
2. Ingest передаёт метрики, сырые логи и трейсы в аналитику, а запросы символикации — в RabbitMQ.
3. Symbolicator получает задания из RabbitMQ, обращается к S3-хранилищу символов и публикует результаты для аналитики.
4. Аналитика работает с ClickHouse и обменивается данными с Control Plane через gRPC.
5. Frontend обращается к Control Plane; Control Plane хранит метаданные в PostgreSQL через GORM.
6. ML-аналитика взаимодействует с аналитикой через gRPC, с ClickHouse и OpenRouter.
7. Control Plane выгружает новые релизы в OTA-хранилище S3; агент получает OTA-команды и бинарники через Caddy.
8. Добавление нового файла символов инициирует через брокер символикацию и обновление метаданных для аналитики.

На исходной схеме также есть связь между S3-хранилищами OTA и символов. Её назначение и способ реализации нужно уточнить до реализации.

## Пока не определено

- Языки и стек ingest и symbolicator; выбор языка ML-аналитики.
- Браузерный транспорт frontend → Control Plane.
- Форматы контрактов, топология очередей и правила версионирования.
- Механизм развёртывания и локального запуска.
- Назначение связи между двумя S3-хранилищами.
